# 每日財經簡報寄信到 Email（Claude Routine 設定）

讓 Claude **每天自動**把當日「全球財經 + 商業世界」深度簡報寄到你的信箱，
**完全不需要任何 API 金鑰或 GitHub secret** —— 由 Claude 自己上網蒐集、消化成洞察，
再透過 Gmail 連結器寄出。

## 為什麼不用網站的新聞 pipeline？

網站的每日新聞（`briefings.json`）需要外部 LLM 才能把 RSS 原文整理成分級新聞，
在雲端排程環境已停止更新。這個 Routine 改由 **Claude 本身**擔任那個 LLM 角色，
所以不需要 `GEMINI_API_KEY`、不需要付費 API，也不受該 pipeline 卡關影響。

## 一次性設定（約 1 分鐘）

Routine 無法從「Claude Code on the web」的工作階段內建立，必須在網頁 UI 或終端機 CLI 建立：

1. 打開 <https://claude.ai/code/routines> → 點 **New routine**。
2. **Name**：`每日財經簡報寄信`
3. **Prompt / Instructions**：貼上下方「Routine 提示詞」整段。
4. **Repositories**：選 `news-dashboard`（表單需要，本任務其實用不到 repo）。
5. **Environment**：用 **Default**（Trusted 即可 —— Gmail 連結器流量走 Anthropic
   伺服器，不受網路白名單限制）。
6. **Connectors**：保留 **Gmail**，其餘可移除以縮小權限。
7. **Trigger**：選 **Schedule → Daily**，設定你想收信的時間（台北時區自動換算）。
8. **Model**：選最強的模型 —— 這份簡報的價值全在研判品質。
9. 點 **Create**。可先按 **Run now** 測試。

> CLI 替代做法：在終端機（非 web 工作階段）執行 `/schedule`，Claude 會逐步問完並建立。

## Routine 提示詞（原封不動貼上）

```
執行每日財經簡報並寄到我的信箱。收件人：liuaaron1128@gmail.com

【第一步：確認日期】
先確認今天的正確日期（台北時區）。絕對不要從搜尋結果去推斷日期。

【第二步：蒐集資料】用 WebSearch 蒐集最新資料。
來源母體見 repo 的 `src/data/sources.json`（198 個網站，已分好
地區／來源類型／資訊類型／更新節奏）。覆蓋要求：

A. 地區 —— 七區都要掃過，不可只做美國與台灣
   台灣 40｜其他亞太 40（韓國、星、印、東南亞）｜美國 28｜全球 26
   ｜日本 23｜歐洲 21｜中國 20
   ※ 韓國（The Elec／BusinessKorea／KED Global）對半導體與記憶體
     的利潤流向特別關鍵，勿略過。

B. 六大資訊類型 —— 每一類至少查一輪
   財經市場 51｜綜合新聞 48｜數據／研究／揭露 36｜政經政策 35
   ｜經濟學家觀點 17｜產業情報 11
   ※ 政經政策要涵蓋 Fed／日銀／ECB／人行等各國央行動作。
   ※ 經濟學家觀點要具名引用（El-Erian、Martin Wolf、Krugman、
     Roubini、Rogoff、Richard Koo、林毅夫、Raghuram Rajan 等）。
   ※ 產業情報用 DIGITIMES、科技新報、The Elec、日經 Cross Tech。

C. 商業世界（至少佔一半篇幅）
   併購與資本動向｜企業 AI 落地（導入數據、ROI、失敗率、案例）
   ｜創投與新創募資｜產業與供應鏈｜重要財報與經營動態

D. 主題檢查清單 —— 每期逐項確認，沒有進展就寫「今日無」
   □ 能源與地緣政治（油價、荷姆茲、戰事）—— 常是通膨與央行動作的共同上游
   □ 各國央行（Fed／日銀／ECB／人行）
   □ 匯率（台幣、日圓、美元指數）
   □ 關稅與供應鏈重配置（Section 301、越南／印度／墨西哥）
   □ 台灣在地限制（電力與併網、缺工、法規、房市與內需）
   □ 記憶體與關鍵料件價格
   □ 併購與私募退場
   □ 企業 AI 落地與 ROI
   □ 創投募資動向

【第三步：多輪追查關聯】—— 不可只做一輪
找到新聞後，針對每條重要線索**再搜尋第二輪**：查它的背景、相關當事人、
上下游影響、以及與其他線索的關聯。目標是找出「影響鏈」，
而不是產出一份彼此無關的新聞清單。
例：記憶體漲價 → 誰在賺這筆（韓國記憶體廠財報）→ 誰在付這筆
（台廠毛利率）→ 什麼時候完全反映（合約交貨時間差）。

【第四步：找共同上游】
把當期線索排在一起，問一句：這些事有沒有<共同的原因>？
不要把同一件事的多個下游反應當成多件事報。
（實例：Fed／日銀／ECB 同時轉鷹，看起來是三件事，
  但三家都點名能源 —— 上游其實是中東戰爭造成的石油供給衝擊。）

【第五步：寫成決策簡報，不是研究報告】用繁體中文，讀者是企業董事長。
版面必須<分層>，讓他 10 秒、1 分鐘、10 分鐘各能停在一個完整的層次：

  第 1 層｜結論：3 句話。每句一個完整判斷，不是摘要。
  第 2 層｜關鍵數字：4 個，大字呈現，附前值與意義。
  第 3 層｜決策：3 個，每個都要有<明確期限>與<為什麼是現在>。
          必須放在報告<前段>，不可埋在最後。
  第 4 層｜影響地圖：一張圖，從上游根源畫到「你的損益表」。
  第 5 層｜深度分析：分主題展開，每個主題結尾要有「所以呢」。
  第 6 層｜追蹤：本週要盯的數字，標出最優先的那一個。

其他要求：
- 核心研判要指出「市場共識是什麼、我認為哪裡想錯了」。
- 數字要同口徑才並列；不同口徑時改用<衍生比率>
  （例：獲利增速 ÷ 營收增速，>1 為毛利擴張、<1 為毛利被侵蝕）。
- 每個主題都要回答「對你的意涵」，不能只描述事件。
- 適時用表格、橫向長條圖、數字塊。
- 結尾註明資料來源與「僅供參考，非投資建議」。
- 今日核心研判（3–5 段）：串起各項訊號、明確點出「背離或共振」，並指出
  「市場共識是什麼、我認為哪裡想錯了」。要給判斷，不要只複述數字。
- 市場快照：表格化關鍵數字，標示變動方向。
- 以「主軸」組織內容，不要用零散新聞清單。每個主軸串起多則相關消息，
  並明確寫出影響鏈。每則採多層結構：
  發生什麼 → 第一序效應 → 第二序效應（多數人沒算到的）→ 對你的意涵
  → 觸發條件 → 觀察點
- 商業世界區塊要有實際數字（金額、百分比、公司名），並做「模式判讀」：
  這些交易合起來說明了什麼趨勢。
- 給董事長的問題：本週可立即行動的具體提問（3–5 題）。
- 適合時用表格與圖表（橫向長條圖、數字塊）呈現對比與量級。
- 未來一週觀察行事曆。
- 結尾註明資料來源與「僅供參考，非投資建議」。

【第六步：寄信】用 Gmail 的 send_message 寄出：
- 主旨：📊 每日財經簡報 — YYYY/MM/DD（週X）｜<當日最關鍵的一句話>
- HTML 卡片排版：深色漸層標題列（含當日轉折摘要）、核心研判方框（內含
  「我認為市場想錯的地方」高亮框）、市場快照表格、每則新聞獨立卡片並以粗體
  標籤分隔各層、商業數據用表格、深色底的「給董事長的三個問題」區塊、
  觀察行事曆、來源註記。
- 同時提供純文字 body 作為 fallback。

若 Gmail 工具不可用，請直接回報，不要靜默結束。
```

## 品質準則（寫給執行這份任務的 Claude）

- **先查日期再查新聞。** 曾發生過從搜尋結果推斷日期、導致寄出兩週前行情的錯誤。
- **一定要做第二輪追查。** 只做一輪的產出是新聞摘要，不是情報。
- **覆蓋七大地區。** 只做美＋台會漏掉關鍵線索（例如記憶體利潤流向要看韓國財報）。
- **數字要能比較。** 不要把不同口徑的指標並列（例如營業利益率 vs 淨利率）；
  要嘛換成同口徑，要嘛明確標註差異。
- **圖表尺度要合理。** 一根長條把其他壓成看不見時，改用分開的數字塊呈現。
- **推算的數字要標註「本站計算」。**
- **決策放前面。** 讀者要先看到「要做什麼」，再看「為什麼」。
- **找共同上游。** 三個現象若共用一個原因，就該當一件事報。
- **不確定就明說。** 取不到最新值時標註資料所屬期間，不要用舊值假裝新值。
- **數字要有出處、要最新。** 標明是哪一個交易日的收盤。
- **價值在研判不在轉述。** 每一則都要回答「所以呢？對我有什麼影響？」
- **商業內容不可被市場行情擠掉。** 董事長要的是經營決策情報，不只是盤勢。
- 找不到某塊資料時，明說「今日無重大進展」，不要編造。
